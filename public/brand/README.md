# Brand assets

These five files are generated by `scripts/prepare-supplied-assets.mjs` from
`assets-supplied/Foundry logo.pdf`, the master the content owner supplied:

```
foundry-logo-blue.svg    foundry-logo-white.svg    foundry-logo-black.svg
foundry-icon-blue.svg    foundry-icon-white.svg
```

The PDF's page box is 355.677 × 134.703 — the exact geometry recorded in
buildspec Appendix A.1. The artwork is a single flat colour, so the white and
black variants substitute that one fill value, and the symbol variants narrow
the viewBox to the symbol's 77.01 units. No path is ever edited, and the script
asserts that every `d=` attribute is byte-identical across all five outputs.

Never edit these by hand. Never recreate the logotype with text, and never
recolour it with a CSS filter — pick the variant that suits the surface.

## Two open questions for the brand owner

1. **The blue does not match the token.** The PDF renders `#28428C`; the
   `--color-foundry-blue` token is `#00308F`. That is the signature of a
   CMYK→sRGB conversion on export. Which is correct?
2. **The delivered SVG masters are still preferable.** Appendix A.1 lists five
   originals with known hashes. They carry the brand's own per-variant optical
   corrections rather than a mechanical colour substitution. If you have them,
   drop them in here — `pnpm brand:verify` will recognise them as the delivered
   masters automatically.

## Verifying

```bash
pnpm brand:verify          # reports which source each file came from
pnpm brand:verify:strict   # also fails when a file is missing (production gate)
```
